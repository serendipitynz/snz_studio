## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-92 のドキュメント。読み手は 2 つで、文書も 2 つに分かれる。README と README.ja は利用者向け、AGENTS と AGENTS.ja はリリース作業者向け。和英の両方を同じ節・同じ記述でそろえる。

## 利用者向け (README / README.ja)

- アプリは GitHub Releases から自分で更新できること。自動確認は設定でオフにできること。
- 更新機能を載せた最初の版より前の版 (v0.1.0 など) には更新機能が無いので、一度だけ手動で入れ替える必要があること。同じ文を、その版のリリースノートにも書く (リリース作業のときに手で足す)。
- **Windows はインストール先が変わること。** その版から per-user インストール (`%LOCALAPPDATA%\Programs`) になり、Program Files に入っている v0.1.0 は自動では消えない。手動で入れ替えるときに、古いほうを「アプリと機能」からアンインストールしてもらう。データは別の場所にあるので引き継がれる。これもリリースノートに書く。
- 更新のとき、システムがパスワードや管理者の承認を求めることがあること。実際に観測したことだけを書き、観測していない警告 (Windows の SmartScreen など) は書かない。

## リリース作業者向け (AGENTS / AGENTS.ja のリリースの節)

- draft の Release を公開した時点で更新が配られ始めること。公開するまでは、インストール済みのアプリからは見えない。
- 新しく増えた secret (更新署名鍵) と、その登録手順。
- **鍵の運用**: 秘密鍵をどこに保管しているか。秘密鍵を失くすか差し替えると、インストール済みのアプリはすべて新しい版を受け付けなくなる。アプリが信用するのは、自分のバイナリに埋め込まれた公開鍵だけだからである。その場合、利用者全員に手動で入れ直してもらうしかない。つまり障害対応の問題ではなく、バックアップの問題である。
- latest.json を `attach` ジョブ 1 つで書いている理由と、URL をタグに固定している理由。後の変更で崩さないようにするため。
- モデル用のリリースがあっても、アプリが版タグだけを選ぶので更新の確認には影響しないこと。
