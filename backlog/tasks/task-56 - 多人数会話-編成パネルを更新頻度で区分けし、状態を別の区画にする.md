## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-47 (#47) の後のオーナーの実窓の確認 (2026-09-26) で出た、複数エージェントチャットの編成パネル (`ParticipantPanel`) の構成についての指摘。オーナーの注記: 「会話の設定・参加者の編成の内容粒度を精査したい」。

オーナーの注記による、今の欄の更新頻度:
- 会話の設定
  - ターン進行ルール・場面設定: 更新頻度は低め。
  - 共通の状態: 会話の状況に応じて変わる。
- 参加者ごと
  - 表示名・役割プロンプト・プロジェクト資料を渡す: 更新頻度は低め。
  - 状態: 会話の状況に応じて変わる。
  - 接続先・接続確認・モデル: 基本的に最初だけ。

オーナーの素案 (2026-09-26、画面の注記から):
- パネルの見出しを「編成」から「インスペクタ」に変える。単独チャットのコンテキストインスペクタと呼び方を揃えると読んだ。見出し帯のトリガーの名前と、読み上げの語も合わせる。
- 「状態」の区画 (状態パネル) を切り出して、パネルに足す。素案の図では、既存の区画の前 (上) に置いている。
  - 中身: 「共通の状態」の欄と保存。続けて、参加者ごとにその表示名を見出しにし、その参加者の「状態」の欄と保存を置く。並びは編成の順。
- 「会話の設定」の区画から「共通の状態」を、参加者のカードから「状態」を、それぞれ状態の区画へ移す。会話の設定と参加者のカードには、更新頻度の低い欄と接続の欄が残る。

着手時に確かめること:
- 状態の区画の置き場所。素案の図では、インスペクタの中の先頭の区画に見える。インスペクタの外の別の区画にするかどうかを確かめる。
- 「基本的に最初だけ」の接続の欄 (接続先・接続確認・モデル) を、畳んだ区画 (doc-9 §6.3) にするか。素案は手を入れていないので、変えないのが既定。
- 除籍した参加者の状態は、状態の区画に出さない。今も編成にいる参加者だけに状態の欄がある。

保つもの:
- 状態のシートは、ターンの実行中・自動進行中も編集と保存ができる (design §4.7)。
- 書きかけは、区画を消しても残る (TASK-47)。状態の欄を参加者のカードから移しても、保存値からの書きかけの初期化 (保存値を key にした作り直し) の振る舞いを変えない。
