## 背景

「呼ばれた人が答える」会話は既存の 3 規則では出ない。TASK-28 の spike が、スコア方式 (`weighted`) と、
呼びかけ先を最優先する順位規則 (`addressed_first`) を 60 ターンのシミュレーションで比較し、
**`weighted` を採用**して `docs/multi-agent-chat-design.md` §4.6 に記録した。

決め手は複数呼びかけである。1 発言が 2 人を呼ぶ (「A さんと B さん、どう思う？」) と、順位規則は一方を捨てるしかなく、
捨てられた側が話すまでの待ちが 14 ターン・一巡ターン数 17 に伸びる。`weighted` なら呼びかけ先の全員が
×0.5 を免れ、残りの係数がどちらから話すかを決めるので、待ち 5 ターン・一巡 8 に収まる (§4.6.3 読み取り 3)。

**呼びかけ**とは、ある発言の本文が、次に話す相手として編成の参加者 1 人以上の表示名を挙げていることを指す。
`manual` の人間による指名とも、§7「将来」の進行役による指名とも別物である。

## やること (設計は §4.6.1 / §4.6.4 / §4.6.5 / §4.6.7)

- migration で、発言に紐づく呼びかけ先の参加者 id の**集合**を保存する場所を足す (0 個 = 呼びかけ無し)。
  1 発言が複数を呼べることが `weighted` を採る理由そのものなので、単数の列に切り詰めない。
- 呼びかけの検出を発言の**保存時**に確定して書く。後から本文を読み直す形にしない (§2: 再起動をまたいで
  同じ答えになること)。判定のための追加の LLM 呼び出しはしない。
  - (a) 役割リマインド (§4.3) に `[次: 表示名]` の末尾指示子を足し (複数なら読点区切り)、保存前に末尾の 1 行だけ
    剥がして id に解決する。編成に一致しない表示名はその 1 件だけ捨てる。一致 0 件なら呼びかけ無しとしたうえで
    指示子は剥がす (本文に制御用の記法を残さない)。
  - (b) (a) が空振りしたときだけ名前の照合。最終文に現れた編成の表示名のうち自分自身を除いた全員を呼びかけ先とする。
    最終文に限り、表示名 2 文字以上に限る (日本語の表示名は単語境界で切れず部分文字列一致になるため)。
    編成の全員が一致したら呼びかけ無しとする (全員が ×0.5 を免れると呼びかけ無しと同じ並びになり、検出が何も足さない)。
  - 人間の介入発言にも (b) をかける (`POST /messages` 側。介入が直前の話者を呼ぶ場合、かけないと届かない)。
  - 自分自身への呼びかけは捨てる。
- `turn_rule` に 4 つ目の値 `weighted` を足す。ターン開始時に編成の参加者ごとに重み (係数の積) を求め、最大が話す:

  | 係数 | 掛かる相手 | 値 |
  | --- | --- | --- |
  | 連続発言の抑制 | 末尾のメッセージを書いた参加者。末尾が人間の介入発言なら誰にも掛からない | ×0.2 |
  | 直近発言の抑制 | 直近 n ターン (n = 編成の人数) に発言した参加者。進行役は対象外 | ×0.85 |
  | 呼びかけの集中 | 末尾のメッセージが呼びかけた参加者以外の全員 (呼びかけ先が複数ならその全員が免れる) | ×0.5 |
  | 名簿順の維持 | 直近の参加者発言の次に当たる参加者以外の全員 | ×0.95 |

  同点規則は「沈黙が長い側 → なお同点なら名簿順の先」。一度も発言していない参加者は、発言したことのある
  どの参加者よりも沈黙が長いものとして扱う (60 ターンで 2〜8 回同点になるので必須、§4.6.3 読み取り 4)。
  正規化 (合計 1) は表示のときだけ行う。
- 編成パネルのターン進行ルール選択に `weighted` を足し、1 行の説明を添える。
- TASK-33 の `speaker` イベントに重みの内訳を載せる (フロント側に算術を足さない)。

## 前提

既存の `round_robin` / `manual` / `facilitator_alternating` の振る舞いは**一切変えない**。呼びかけ追従を
chat 単位の真偽値設定にして既存 3 規則すべてに効かせる形は採らない (呼びかけで名簿順を外れる `round_robin` は
もはや `round_robin` ではない、§4.6.4)。

呼びかけの集中を ×0.5 より強めない。呼びかけ先の重みは最低 0.85×0.95 = 0.8075、他の最大は 0.5 なので、
×0.5 の時点で呼びかけ先が必ず勝つ (§4.6.3 読み取り 1)。

## 検証シナリオ

- 同梱プリセット `trpg-table` (GM + プレイヤー 2 名) を `weighted` で回し、GM が名指ししたプレイヤーが次に話すこと、
  名指しの無いターンは進行役が挟まる形になることを実機で確認する。
- 1 発言が 2 人を呼ぶケースで、両方が短いターン数のうちに話すことを確認する。
- 人間が直前の話者を名指しで呼んだとき、その participant が続けて話すことを確認する。
- 小型モデルが `[次: 表示名]` をどの程度書くか (検出 (a) の当たり方) を実機で測り、(b) のフォールバックが
  どれだけ働くかを記録する。
