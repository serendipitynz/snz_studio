## 背景

「呼ばれた人が答える」会話は既存の 3 規則では出ない。TASK-28 の spike が、スコア方式 (`weighted`) と、
呼びかけ先を最優先する順位規則 (`addressed_first`) を 60 ターンのシミュレーションで比較し、
**`weighted` を採用**して `docs/multi-agent-chat-design.md` §4.6 に記録した (ユーザー判断)。

係数は **3 つ**。起票時の原案から 2 点変えてある。

1. **呼びかけは「末尾のメッセージの呼びかけ先以外を ×0.5」ではなく「直近 n 参加者発言の窓のうち
   未応答の呼びかけを持つ参加者に ×1.2」**。原案は末尾 1 つしか読まないので、`[A, B]` の A が話した瞬間に
   B への呼びかけが消える (§4.6.4)。
2. **「名簿順の次以外を ×0.95」は置かない**。発言順を変えておらず (呼びかけの無い編成では戻しても全指標が
   一致し、変わるのは同点の回数だけ)、一方で呼びかけの必要加点を `1/0.85` から `1/(0.85×0.95)` に上げていた。
   戻すと ×1.2 では足りず即時追従率が 21/21 から 14/21 に落ちる (§4.6.3 読み取り 1)。

`addressed_first` を採らない理由は、呼びかけが常に他を先取りすると呼ばれない参加者が飢えること
(一巡ターン数 30、採用案は 8。§4.6.3 読み取り 6)。

**呼びかけ**とは、ある発言の本文が、次に話す相手として編成の参加者 1 人以上の表示名を挙げていることを指す。
`manual` の人間による指名とも、§7「将来」の進行役による指名とも別物である。

## やること (設計は §4.6.1 / §4.6.4 / §4.6.5 / §4.6.7)

- migration で、発言に紐づく呼びかけ先の参加者 id の**集合**を保存する場所を足す (0 個 = 呼びかけ無し)。
- 呼びかけの検出を発言の**保存時**に確定して書く。後から本文を読み直す形にしない (§2)。窓のあいだ何度も
  読み返されるので、再解釈のたびに答えが変わる余地を残さない。判定のための追加の LLM 呼び出しはしない。
  - (a) 役割リマインド (§4.3) に `[次: 表示名]` の末尾指示子を足し (複数なら読点区切り)、保存前に末尾の 1 行だけ
    剥がして id に解決する。編成に一致しない表示名はその 1 件だけ捨てる。一致 0 件なら呼びかけ無しとしたうえで
    指示子は剥がす (本文に制御用の記法を残さない)。
  - (b) (a) が空振りしたときだけ名前の照合。最終文に現れた編成の表示名のうち自分自身を除いた全員を呼びかけ先とする。
    最終文に限り、表示名 2 文字以上に限る。**編成の全員が一致しても捨てない** (§4.6.5)。
  - 人間の介入発言にも (b) をかける (`POST /messages` 側)。
- `turn_rule` に 4 つ目の値 `weighted` を足す。ターン開始時に編成の参加者ごとに重み (係数の積) を求め、最大が話す:

  | 係数 | 掛かる相手 | 値 |
  | --- | --- | --- |
  | 連続発言の抑制 | 末尾のメッセージを書いた参加者。末尾が人間の介入発言なら誰にも掛からない | ×0.2 |
  | 直近発言の抑制 | 直近 n ターン (n = 編成の人数) に発言した参加者。進行役は対象外 | ×0.85 |
  | 未応答の呼びかけの加点 | 未応答の呼びかけを持つ参加者 | ×1.2 |

  - **呼びかけの窓** = 直近 n 件の参加者発言 (n = 編成の人数)。人間の介入発言は窓を消費しないが、
    介入が**した**呼びかけは読む。窓の大きさは結果にほとんど影響しないので (§4.6.3 読み取り 3)、
    直近発言の抑制の窓と同じ値にして説明を 1 つに保つ。
  - **未応答の呼びかけ** = 窓のうちに呼びかけられ、その呼びかけより後にまだ発言していない状態。
    **応答したら加点は消える** (§4.6.3 読み取り 5)。
  - **同点規則は「沈黙が長い側 → なお同点なら名簿順の先」。未発言の参加者は最も沈黙が長いものとして扱う。**
    これがこの規則の中核である。係数が 3 つとも離散値なので重みが並ぶことが多く (60 ターン中 16〜21 回、
    進行役の居ない 3 人編成では 59 回)、そこで誰が先かは同点規則が決めている (§4.6.3 読み取り 4)。
    名簿順だけの同点規則にすると一巡ターン数 8 → 12、最大発言シェア 32% → 40% に悪化する。
  - 正規化 (合計 1) は表示のときだけ行う。
  - **人間の介入発言の後に進行役を強制する上書きは入れない** (§4.6.7)。
- 編成パネルのターン進行ルール選択に `weighted` を足し、1 行の説明を添える。
- TASK-33 の `speaker` イベントに重みの内訳を載せる (フロント側に算術を足さない)。

## 加点の値 (§4.6.1 / §4.6.3 読み取り 2)

呼びかけが越えなければならない相手は、直近発言の抑制を免除された進行役である。定常状態では全員が
×0.85 を受けているのでその係数は比較から消え、条件は **加点 > 1/0.85 ≈ 1.176** の一本になる。
×1.1 は下回るので呼びかけが通らない (即時追従率 11/21、加点なしと同値)。
**×1.2 / ×1.3 / ×2.0 は全シナリオで完全に一致する** (1.176 を越えた時点で飽和する)。
値を動かすなら 1.176 より上に限り、動かしたら `tools/turn-score-sim` で測り直す。
進行役が居ない編成ではこの境界そのものが無い。

## 範囲外

- **`talkativeness` (参加者ごとの発言頻度) は入れない** (§4.6.10)。決定的なエンジンでは定数係数に
  なるしかなく、値の低い参加者が構造的に締め出される (係数 0.8 で一巡ターン数が 7 → 39、0.5 で一巡せず)。
  入れるなら沈黙を連続量にする変更と抱き合わせが必要で、それは規則の形の変更になる。
- **応答されなかった呼びかけを窓より先へ持ち越さない** (§4.6.4)。持ち越すには待ち行列が必要で、
  §2 の「サーバー側に進行状態を持たない」と両立させる導出の設計が別途要る。
- **応答者リスト方式 (1 リクエストで複数人が話す) は移さない** (§4.6.10)。1 リクエスト = 1 ターンは §4.1 の決定。

## 前提

既存の `round_robin` / `manual` / `facilitator_alternating` の振る舞いは**一切変えない**。呼びかけ追従を
chat 単位の真偽値設定にして既存 3 規則すべてに効かせる形は採らない (§4.6.4)。

## 検証シナリオ

- 同梱プリセット `trpg-table` (GM + プレイヤー 2 名) を `weighted` で回し、GM が名指ししたプレイヤーが次に話すこと、
  名指しの無いターンは進行役が挟まる形になることを実機で確認する。
- 1 発言が 2 人を呼ぶケースで、**両方が窓のうちに話す**ことを確認する。
- 人間が直前の話者を名指しで呼んだとき、その participant が**呼びかけの窓のうちに**話すことを確認する。
- 小型モデルが `[次: 表示名]` をどの程度書くか (検出 (a) の当たり方) を実機で測り、(b) のフォールバックが
  どれだけ働くかを記録する。
