## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. 配色の縮退 (AC#1・#2): ThemeController が「保存値が収録外か」(読んだ時点の判定) と「直前の選択を保存できなかったか」(writeKey の成否) を返す。設定モーダルの外観の区画に、収録外は案内の段の告知 (閉じられる。描いている組と、選び直すと置き換わることを述べる)、保存の失敗は失敗の段の告知 (この起動の間は効くこと・保存できなかったこと) を出す (doc-9 §7)。保存値は開いただけでは書き換えない。
2. 見出し (AC#6): 外観・言語・接続の区画のバッジを見出しの語 (SubsectionTitle) に戻す。確認ダイアログは heading と confirmLabel を必須にし、「OK」の既定を消す。見出しの無かった呼び出し (説明文の置き換え2か所) に見出しを足す。本文の語は fg にする。
3. 接続の点 (AC#3): StatusDot を状態バッジ (語「接続済み」/「未接続」、成功/危険の調子、面と輪郭) にする。
4. 破棄前確認 (AC#4): 接続の下書きが保存値と違うとき、閉じるボタンと Escape で既存の discard の確認を出す (既定は留まる側)。保存中は閉じず、閉じるボタンは理由を持つ。外観と言語は選んだ時点で効くので書きかけに数えない。
5. 進捗 (AC#5): Progress に量が分からない変種 (流れる印、reduced motion で遅く) を足し、埋め込みモデルの取得を量が分かる進捗 (転送量と割合) で描く。total が 0 の間は量が分からない変種。始まりと量が分かったときだけ読み上げる。
6. 無効と処理中 (AC#7): 保存ボタンを ActionButton にし、読み込み中・変更が無いときは disabledReason、保存中は busy (語と幅を保つ。図形を持たせる)。読み込みと保存の失敗は接続の区画の中に FailureNotice で出す。
7. check:client・build:client を通し、Vite の開発サーバー + Playwright (Chromium / WebKit、/api は route で固定) で4配色の比・キーボードの到達・保存値の読み替えと保存の失敗・破棄前確認・進捗を確かめ、測定環境とともに Notes に書く。

## 変えたもの
- 配色の縮退 (AC#1・#2): `ThemeController` が `storedChoiceUnknown` (読んだ保存値が収録外) と `saveFailed` (直前の選択を保存できなかった) を返す。2つのキーの書き込みを `writeChoice` の1か所にまとめ、成否を返すようにした。収録外の値は、開いただけ・案内を閉じただけでは書き換えない。ここで選び直して保存できたときだけ置き換わり、案内が消える。設定モーダルの外観の区画に、収録外は案内の段の告知 (新しい `InfoNotice`。閉じられる。閉じると焦点をテーマの選択欄へ移す。開き直すとまた出る)、保存の失敗は失敗の段の告知 (「アプリを終了するまで効きますが、保存できませんでした」) を出す (doc-9 §7 の段の割り当て)。
- 見出し (AC#6): 外観・言語・接続の区画のバッジを見出し h3 (`SubsectionTitle`) に戻した。言語の区画の欄の名は、見出しと同じ語にならないよう「表示言語」にした。確認ダイアログは `heading` と `confirmLabel` を必須にし、「OK」の既定と `common.ok` を消した。見出しを持たなかった説明文の置き換えの確認 (ImageDocumentDialog・ImageDocumentEditor) に「説明文を置き換え」を足した。本文の語を muted から ink にした (doc-9 §6.6 の本体の語 `fg`)。
- 接続の点 (AC#3): `StatusDot` をやめ、状態バッジ `StateBadge` (語「接続済み」/「未接続」、成功/危険の調子の面と輪郭。doc-8 §6.5) にした。設定の読み込み前は出さない (前は読み込み中に「未接続」の色を出していた)。成功の調子の役割が ThemeTokens に無かったので `success`・`successSoft`・`onSuccessSoft` を足した。標準・Solarized は共通トークン、追加の5配色系統は今までの接続の点と同じアクセントから作る。使われなくなった `statusOkGlow` は消した。
- 破棄前確認 (AC#4): 接続の下書きが保存値と違うとき、閉じるボタンと Escape で既存の破棄前確認 (「変更を破棄しますか？」、既定の焦点は「編集を続ける」) を出す。外観と言語は選んだ時点で効くので下書きに数えない。保存中は閉じず、閉じるボタンは理由を持つ。
  - 直したもの: 設定の読み込み (接続確認を待つので数秒掛かり得る) が終わる前に書いた欄が、読み込みの結果で上書きされていた。確認を足すと「書いたのに確認が出ずに消える」形になるので、読み込み中に書き換えた欄は残し、下書きとして数えるようにした。
- 進捗 (AC#5): `Progress` に量が分からない変種 (帯の中を流れる印。周期 motion.spin の2倍、動きを減らす設定で motion.spinReduced の2倍。止めない) と `fullWidth` を足した。埋め込みモデルの取得は、量が分かれば塗りと転送量・割合 (「12.0 MB / 30.0 MB (40%)」)、total が 0 の間 (最初の塊が届くまで) は流れる印で描く。読み上げは始まったときと量が分かったときだけ。語は「埋め込みモデルをダウンロード中です」と「その間はキーワード検索が有効です。」に分けた (1つの語だと量の語と並ばず折れて、量が分かった時点で高さが変わったため)。
- 無効と処理中 (AC#7): 保存ボタンを ActionButton にした。読み込み中は「設定を読み込み中…」、変更が無いときは「変更がありません」を理由に持ち、焦点を受ける。保存中は語「設定を保存」と幅を保ち、図形域に処理中の図形を出す。読み込みの失敗は接続の区画の先頭、保存の失敗は保存ボタンの直上に FailureNotice で出す (前はモーダルの先頭の ErrorText)。この画面に `:disabled` の部品は無い。
- `docs/current-spec(.ja).md` の接続設定の節に、設定モーダルの振る舞いを書いた。

操作 (Chromium と WebKit の両方で、挙動 78 項目・進捗 28 項目が通った):
- 収録外: `snz.theme.family=dracula` と `snz.theme.mode=sepia` のそれぞれで、標準・自動で描き、案内 (図形の名「案内」) を出し、保存値は開いても案内を閉じても変わらない。閉じると焦点はテーマの選択欄へ移る。開き直すとまた出る。選び直すと案内が消え、新しい選択が2つのキーに入る。収録済みの値 (one / dark) では出ない。
- 保存の失敗: 書き込みを失敗させて明暗を Dark にすると、画面の地の色が変わり、失敗の告知が出て、保存値は light のまま。書ける状態で選び直すと告知が消える。
- 破棄前確認: 書きかけが無ければ Escape で閉じる。LLM エンドポイントを書き換えて Escape / 閉じるボタンを押すと確認が出て、焦点は「編集を続ける」。Escape は確認だけを閉じ、下書きは残る。「破棄する」で閉じ、開き直すと保存値から始まる。同じ値に書き戻したときは確認を出さずに閉じる。読み込み中 (800ms 遅らせた) に書いた欄は読み込み後も残り、閉じると確認が出る。
- 無効と処理中: 変更が無い保存は aria-disabled で理由「変更がありません」、焦点を受け、Enter で要求を出さない。読み込み中の理由は「設定を読み込み中…」。保存中は aria-busy で語と幅 (差 0.5px 未満) を保ち、2回目の押下で要求は増えない (1回)。閉じるボタンは理由を持ち、Escape でも閉じない。保存後は確認なしで閉じる。保存の失敗は接続の区画の中、保存ボタンの直上に出て、下書きは残る。読み込みの失敗は接続の区画に出て、状態バッジは出さない。

## レビュー 1 回目の対応 (#48)
- [P2] 接続の状態が、書き換えた欄の横で保存値の結果を語で言い切っていた: 直した。状態は保存値に対する確認なので、下書きがそのエンドポイント・モデル (埋め込みは取得元も) を変えている間は出さない。書き戻すと出る。
- [P3] 読み込みの失敗の後に保存できた: 直した。書いていない欄が空で送られて保存値を消すので、保存ボタンは理由「設定を読み込めなかったため保存できません。設定を開き直してください。」を持つ。これで「保存が通っても読み込みの失敗が残る」指摘 (P3) も起きなくなった。
- [P3] 保存中の Escape が何も言わない: 直した。閉じるボタンと同じ理由を読み上げる。
- [P3] 読み込み中に書いてから消した欄は読み込み結果で埋まる: 意図どおり (空の欄は「書いていない」と区別しない)。current-spec の語を「空でない値を書いた欄」に直した。
- [P3] 状態バッジの語が入力欄の名に入る (「LLM エンドポイント 接続済み」): そのままにした。欄を読んだときに接続の状態も届くので、利用者に役立つ。
- [P3] InfoNotice が FailureNotice.tsx にある: この PR では動かさない (改名は TASK-45〜47 の取り込みを全部触る)。警告の段を足すときに Notice.tsx へまとめる。
