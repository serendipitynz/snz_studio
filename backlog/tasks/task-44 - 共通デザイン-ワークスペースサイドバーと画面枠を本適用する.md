## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. ThemeTokens に現在地の描画が読む3値を足す: surfaceSelected・selected・inkStrong。標準 と Solarized は themes/snz.ts が共通の役割 (surface-selected・selected・fg-strong) から写し、追加の5配色系統は buildTokens が今の見た目から導く (面は accentSoft と同じ洗い、帯と枠はアクセント、語は本文色)。
2. SidebarLink の現在地を $active から aria-current の属性で描く: 面 surfaceSelected、外周の枠と左端 3px の帯 (border.band) を selected、語 inkStrong。hover は現在地でない行だけ。チャットを見ている間のプロジェクトは aria-current="true" (その中にいる)、プロジェクト詳細では "page"。
3. doc-9 §6.11 のメニューの振る舞いを1つのフック (components/usePopupMenu.ts) に集め、チャットの種類のメニューと畳まれた入口が共有する: 開くと最初の項目へ焦点、↓↑ は端で回る、Home / End、Escape で閉じてトリガーへ戻す (入れ子では内側だけ)、Tab / Shift+Tab は閉じて焦点を引き戻さない (ブラウザの移動が済んでから閉じる)、外側の押下で閉じる。トリガーの ↓ / ↑ で最初 / 最後の項目を開く。
4. WorkspaceSidebar を 900px 以下 (matchMedia) で畳まれた入口へ切り替える: 本体の上に貼り付く細い帯 (ロゴ + 「メニュー」のトリガー、aria-expanded / aria-controls) と、開いたときだけ本文の上へ重なる行き先の並び (サイドバーと同じ中身と設定ボタン)。行き先を選ぶと閉じる。
5. チャットを作成中の + ボタンを disabled (焦点から外れる) から aria-busy へ改め、図形を同じ寸法の処理中の図形に差し替え、押下を受けない。名札は残し、title で作成中を述べる。
6. ChatPage の列指定を style から $columns へ移し、900px 以下の1列の指定が効くようにする。
7. check:client・build:client を通し、Vite の開発サーバーで4配色の現在地の比 (枠・帯 対 非選択の同じ箇所、語 対 面) を測り、キーボードだけで広い / 狭い両方の全操作へ届くことを確かめる。

## Implementation Notes

- 2026-09-25 AC「スクロールする並びの先頭・末尾の行でも焦点の枠が切れない」を TASK-50 へ移した (オーナーの実窓の確認で NG だったため先に直す)。

## 変えたもの
- 現在地 (AC#1): `SidebarLink` の `$active` をやめ、`aria-current` の属性から描く。画面の現在地と読み上げの現在地が食い違わないようにするため。面 `surfaceSelected`、外周の枠と左端 3px の帯 (`border.band`、inset の影) を `selected`、語を `inkStrong` (fg-strong)。hover の面は現在地でない行だけに掛ける。チャットを見ている間は、そのプロジェクトの行を `aria-current="true"` (その中にいる)、チャットの行を `"page"` にした。見え方は同じ。`ThemeTokens` に `surfaceSelected`・`selected`・`inkStrong` を足した。標準 と Solarized は共通の役割から写し、追加の5配色系統は今までの見た目 (アクセントの 12% の洗い) から導く。
- 畳まれた入口 (AC#2): 900px 以下 (`NARROW_MEDIA`。`WorkspaceShell` の1列の境と同じ値を共有する) では、`WorkspaceSidebar` がサイドバーの代わりに、上端に貼り付く細い帯 (ロゴ + 「メニュー」のトリガー。`aria-expanded`・`aria-controls`) を描く。開くと行き先の並び (サイドバーと同じ中身 + 設定) が本文の上に重なり、本文は動かない。帯を貼り付けにしたのは、トリガーがスクロールで画面の外へ出たら閉じる規則 (doc-9 §6.11・§5.3) を、閉じる処理ではなく、外へ出ない配置で満たすため。行き先を選ぶ・設定を開くと閉じて、トリガーへ焦点を戻す。幅が変わって変種が切り替わるときは、開いていたメニューを閉じる。`ChatPage` はインスペクタを畳んだときの列を `style` で指定していて、900px 以下の1列の指定より強かった。これを `$columns` へ移した。
- メニュー (AC#3): doc-9 §6.11 の振る舞いを `components/usePopupMenu.ts` にまとめ、チャットの種類のメニューと畳まれた入口の両方がこれを使う。開くと最初の項目に焦点。↓↑ は端で反対側へ回る。Home / End。Escape は一番内側だけを閉じてトリガーへ戻す (入口の中の種類のメニューでは、種類のメニューだけが閉じる)。外側を押すと閉じる。トリガーで ↓ / ↑ を押すと、最初 / 最後の項目を開く。Tab / Shift+Tab は閉じ、焦点をトリガーへ引き戻さない。Tab の処理は「ブラウザが焦点を動かし終えてから、焦点がメニューの外なら閉じる」の1つの規則にした。先に閉じると、焦点のある項目が焦点の移る前に消えるため。種類のメニューの項目は `tabIndex=-1` なので、Tab 1回で閉じる。入口の並びの項目はリンクで Tab の順にも入るので、Tab は行き先の間を進み、並びの外へ出たときに閉じる (snz-design の説明用実例 `nav.js` の focusout と同じ扱い)。種類のメニューの項目に焦点の枠が無かったので `focusRing` を足し、メニューの外周の罫を `line-control` にした (doc-9 §6.11 のトークン用途)。
- 処理中と無効 (AC#4): チャットを作成している間の + ボタンは `disabled` で焦点から外れていた。これを `aria-busy` に変えた。焦点を受けたまま、名札「チャットを作成」と 34px の幅を保ち、+ の場所に処理中の図形を描き、押下を受けない。title は「チャットを作成しています…」。選ぶとメニューを閉じて、先にトリガーへ焦点を戻すので、処理中の表示は利用者が押したボタンの上に出る。この変更で、この画面に無効 (disabled) の操作部品は残らない。
- 補助文 (doc-5 §3.2 の測定で見つけて直した): サイドバーのチャット数「(3)」と「(無題)」は、`Subtle` に不透明度 0.72 / 0.78 を掛けていて、4.5:1 を割っていた (2.90〜4.70)。不透明度を外して `muted` のまま描く。

## レビュー 1 回目の対応 (#44)
- [P2] メニューの余白を押すと Escape が効かない (再現した): 焦点が body へ落ちて、メニューの keydown に届かなかった。種類のメニューと入口の並びに `tabIndex=-1` を与え、余白を押したときは並びそのものが焦点を受けるようにした。Tab の止まりにはならないので、枠は描かない。Chromium と WebKit で確かめた。入口: 余白を押すと焦点は並び (DIV)。Escape で閉じてトリガーへ戻る。余白の後の Tab は最初の行き先へ進み、入口は開いたまま。種類のメニュー: 余白を押してから Escape で閉じ、トリガーへ戻る。
- [P3] 作成中の + が押せるように見える: `ENABLED` から `aria-busy="true"` を外し、作成中はカーソルを既定にした。作成中は hover の面も出ない (Chromium で、カーソル default と面の値を確かめた)。
