## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
編成パネル (設計書 §6) の参加者は、接続先とモデルを空欄にするとワークスペース設定の値に
フォールバックする。この挙動が画面から読み取れない。

## 1. 説明が読めない側にだけ置かれている

接続先の入力欄のプレースホルダーには `http://127.0.0.1:1234/v1（空欄ならワークスペースの接続先）`
(`i18n/index.tsx` の `participants.baseUrlPlaceholder`) と書かれているが、編成パネルの幅では
`http://127.0.0.1:1234/v1（空欄な…` までしか表示されず、肝心の説明が切れて読めない (実機で確認)。

一方モデルの入力欄のプレースホルダーは `モデル ID` (`participants.modelPlaceholder`) だけで、
モデルも同じくワークスペース設定にフォールバックすることがどこにも書かれていない。
つまり、読めない側にだけ説明があり、読める側には無い。

そもそもプレースホルダーは入力を始めると消えるため、入力済みの参加者を後から見直すときには
どちらにせよ出てこない。入力欄の下の補足行など、幅で切れず入力後も残る場所へ移すのが素直。

## 2. 接続先とモデルが独立にフォールバックする

`resolveTarget` ([llmclient.go](../internal/service/llmclient.go)) はフィールドごとに独立して
ワークスペース設定へ落ちる:

    baseURL, modelName = defaultBaseURL, defaultModel
    if target.Model != ""   { modelName = target.Model }
    if target.BaseURL != "" { baseURL = target.BaseURL }

このため「接続先だけ入力し、モデルは空欄」の参加者は、〈その参加者の接続先〉+
〈ワークスペースのモデル〉という組み合わせで実行される。そのモデルが当の接続先に存在する
保証はない。プリセット (TASK-5) から作った参加者は接続先もモデルも空で始まるので、
接続先だけ埋めた時点でこの状態を通過する。

この組み合わせで実際にターンを実行したときに何が起きるか (実行前にモデル名の検証があるか、
あるとして何が表示されるか) は未確認。まずそこを確認し、利用者が状況を理解できない形で
失敗するようなら対処する。1 の表示改善だけで足りるのか、フォールバックの単位自体を
見直すべきなのかは、その確認結果で決まる。

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. 編成パネルの参加者エディタで、接続先・モデルの各入力欄の下に補足行を置き、「空欄ならワークスペース設定の接続先 / モデルを使う」ことを常時表示する。プレースホルダーからは説明を外し、例示だけに戻す (幅で切れる問題と、入力後に消える問題の両方がこれで解消する)。ワークスペースの実値は補足行に出さない — GET /api/configuration は接続確認を 3 本走らせるので、補足行のためにパネル表示ごとに呼ぶのは割に合わない。
2. TurnEngine の事前チェック・ログ・ErrEndpointUnavailable のメッセージが、参加者の生の値ではなく解決後の実効値を使うようにする。現状は空欄にした側がメッセージから抜け落ち、何を試して失敗したのか読めない。resolveTarget をそのまま呼んで解決するので、フォールバックの規則は LLMClient と一本のまま。
3. フォールバックの単位 (フィールド独立) は変えない。両方空欄・接続先だけ空欄はいずれも正常に動き、設計 §1 は resolveTarget 無改修を前提にしている。実害は組み合わせが起きることではなく、起きたことが画面から見えないことなので、1 と 2 で対処する。
4. turnengine のテストに、モデル空欄の参加者が失敗したときメッセージが実効モデル名と接続先を名乗ることを追加する。
5. 実機確認の結果 (3 通りの組み合わせ) を Implementation Notes に記録する。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 挙動の実測

`TurnEngine.RunTurn` を実コード経路のまま、`/v1/models` に実在のモデル一覧を返すスタブの
OpenAI 互換エンドポイント (= 生きている LM Studio 相当。既存テストのスタブは空一覧を返すため、
`CheckConnection` の「一覧が空なら何でも通す」経路に逃げてしまい、この件は再現しない) に対して
実行し、3 通りを実測した。手元に LM Studio が無いため、アプリ本体 (WebView) を操作しての確認では
ないことは明記しておく。

| 接続先 | モデル | 結果 |
| --- | --- | --- |
| 空欄 | 空欄 | ワークスペースの接続先・モデルで正常動作 (プリセット作成直後の状態) |
| 入力あり | 空欄 | 参加者の接続先 × **ワークスペースのモデル**。そのモデルがその接続先に無ければ失敗 |
| 空欄 | 入力あり | ワークスペースの接続先 × 参加者のモデル。無ければ失敗 |

失敗時に画面へ出る文字列 (修正前):

    service: participant endpoint did not accept the model: Alice ( at http://127.0.0.1:1234/v1)
    service: participant endpoint did not accept the model: Alice (not-there at )

`ErrEndpointUnavailable` は SSE が始まる前に起きるので 502 + JSON で返り、`api/client.ts` が
`data.error` をそのまま `Error.message` にし、`MultiAgentChatPage` が `<ErrorText>` に素通しする。
つまりこの文字列が利用者の見る全てである。継承した側のフィールドが空白のまま出るため、
「モデルを受け付けなかった」と言いながらモデル名を名乗らない文になっていた。理解できない形の失敗に
当たるので対処した (AC #3)。

## 対処

- `RunTurn` が `resolveTarget` で解決した実効値を事前チェック・ログ・エラー文に使うようにした。
  副次的に、モデルを空欄にした参加者が `EnsureModelLoaded` に必ず弾かれていた (空のモデル名は常に
  false) のも解消し、LM Studio のネイティブ経路が本来通るケースで通るようになった。
- 編成パネルの接続先・モデルの各欄の下に補足行を置き、空欄時にワークスペース設定を継承することと、
  2 つが別々にフォールバックすることを常時表示した。プレースホルダーからは説明を外した。

## フォールバックの単位を変えなかった根拠

起票時に「表示改善で足りるのか、フォールバックの単位自体を見直すべきか」を実測後の判断としていた。
単位 (フィールド独立) は変えない:

- 「両方空欄」「接続先だけ空欄」はいずれも実測で正常に動き、前者はプリセット作成直後の既定状態、
  後者は「ワークスペースの接続先で参加者ごとにモデルを変える」という素直な使い方である。
  単位をまとめる (片方を入力したら両方必須にする等) と、この 2 つを壊す。
- 「接続先だけ入力」も、同じモデル名を複数の LM Studio で配っている構成では正当な組み合わせで、
  存在しないモデルを指すのはその副作用にすぎない。
- 設計 §1 は `resolveTarget` を無改修で使うことを前提にしており、review サービスとも共有している。

実害は組み合わせが起きうること自体ではなく、起きたことが画面から読み取れないことなので、
補足行 (見える化) とエラー文の実効値表示 (失敗時に読める) で対処した。

## 残っている確認 (AC #1 / #2)

描画結果そのものは実機で見ていない。次の 2 点はアプリを起動しての目視が要る:

1. 補足行が編成パネルの幅で折り返して全文読めること、入力後も残ること (AC #1)。
2. 「接続先だけ入力・モデルは空欄」でターンを実行し、失敗時のエラー文が実効モデル名と接続先を
   名乗ること (AC #2)。修正後の期待値は
   `service: participant endpoint did not accept the model: Alice (<ワークスペースのモデル> at <参加者の接続先>)`。

## 実機確認の結果 (2026-09-20)

オーナーがアプリを起動して確認し、AC #1 / #2 をいずれも満たすことを確認した。これで「残っている確認」は解消。

確認の過程で UI に 2 回手を入れた。どちらも実機で見て初めて分かった問題で、起票時の
「プレースホルダーは読めない」と同じ種類の、コード上は妥当に見えるが画面では成立しない類のもの:

1. 入力欄の下に常設の補足行を置く形は、モデル側だけで 4 行を占有し、狭い編成パネルには重すぎた。
   一度読めば以後は読まない説明のために恒久的に場所を使う割に合わないので、ラベル横の `(?)` の
   ツールチップに移した。ホバーとフォーカスの両方で開くのでキーボードだけでも読め、`aria-label` にも
   同じ文を入れてある。吹き出しの幅はテキストなりではなく行幅に固定した — パネルが狭く、
   テキスト幅にすると長い訳文が `overflow: auto` の外へはみ出して切れるため。
2. その吹き出しを下向きに出すと、説明している当の入力欄を覆ってしまい、入力内容が見えなくなった。
   `(?)` に手を伸ばすのはその欄を触っているときなので、いちばん隠してはいけないものを隠していた。
   上向き (`bottom: calc(100% + 6px)`) に変更し、かぶるのは一つ上のコントロール (接続先なら役割
   プロンプト、モデルなら「接続確認」ボタン) だけにした。

## レビューでの追加修正

外部レビュー (Codex CLI) の [P2] を 1 件反映した。事前チェックは解決後の実効値で行う一方、補完には
参加者の生の値を渡していたため、補完側が自前のスナップショットで再解決していた。両者の間に
Configuration の保存が挟まると、チェックしていない組み合わせでターンが走る窓がある。解決を 1 回に
まとめ、その結果を `CreateChatCompletionStream` に渡すようにした。回帰テストは
`TestTurnEngineInheritedTargetSurvivesConfigChange` で、スタブの `/models` ハンドラ (= 事前チェックの
実行中) からワークスペースのモデルを差し替え、それでも承認済みのモデルで補完が走ることを見る。
修正前のコードでは落ちる。回帰テストは計 3 本。
