## Description

## 背景

TASK-19 で人間が任意の 1 発言を選んでメモリに保存できるようになる。しかし議論系の多人数会話
(設計レビュー、アーキテクチャ判断、ブレインストーム) で残したいのは個々の発言ではなく、
複数の発言をまたいで参加者が到達した結論である。結論を人手で書き起こすのは手間で、保存されないまま
会話が流れる。ドキュメント・メモリ → 多人数会話 → メモリ → 後続のチャット、という循環の最後の一歩を埋める。

## 方針

- 多人数会話画面に「結論を要約」操作を置く。要約対象 (会話全体、または人間が選んだ発言から最新まで) を
  アプリの既定 LLM (単独チャットの要約と同じ `SummaryService` が持つ `LLMClient`。参加者の接続先ではない) に渡し、
  結論の下書きを生成する。
  「結論の下書き」とは、参加者が合意した、または人間が採用した判断とその理由を短くまとめた編集可能な文で、
  人間が保存するまでどこにも永続化しないものを指す。
- 生成した下書きは TASK-19 の保存ダイアログに既定の内容として入れる。人間が編集し、kind を選んで保存する。
  既定の kind は semantic。ワンクリック保存はしない。理由は TASK-19 と同じ
  (未検証の推測・役割プロンプト由来の反論が混ざる)。
- 要約のプロンプトには参加者名と役割プロンプトの要旨を渡し、「誰が何を言ったか」ではなく
  「何が決まったか・何が未決か」を、決定と未決を分けて書かせる。役割由来の反論を結論と誤らないため。
- 要約対象には総文字数の上限を設ける (値と根拠は設計時に記録)。会話全体が上限を超えるときは、その旨を表示して
  開始発言の選択を求め、先頭を黙って切り捨てない。既存の `SummaryService.UpdateSummary` は直近 8 件・1 件 220 字に
  切る前提なので流用せず、結論抽出用のプロンプトを別に持つ (使うのは同じ `LLMClient` だけ)。
- isTemporary な会話では TASK-19 と同様に保存を無効化する (下書きの生成と表示は可)。
- 下書きは保存ダイアログ専用で、`chat_summaries` には書かない (設計書 §8.1 の「履歴圧縮に要約を使わない」を保つ)。

## スコープ外

- 会話の終了条件の判定や、終了時の自動要約 (自動進行は人間が止める現行仕様のまま)。
- markdown エクスポート (TASK-10) に要約を含めるかどうか。
- 単独チャットへの同じ操作の追加 (単独チャットは自動抽出と「覚えて」抽出があるため必要が確認されてから)。
