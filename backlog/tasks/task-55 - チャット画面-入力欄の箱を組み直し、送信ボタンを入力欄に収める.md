## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-47 (#47) の後のオーナーの実窓の確認 (2026-09-26) で出た、入力欄の箱 (`Composer` / `ComposerBox`) についての指摘。単独チャットと複数エージェントチャットの両方に掛かる。

指摘:
- 複数エージェントチャットの入力欄の箱が場所を取りすぎている。「停止はターン境界で効きます…」「この画面が切断されても…」の説明文は削除できないか。
- 複数エージェントチャットの、入力欄の下の空間がもったいない。単独チャットは、同じ位置にドキュメントの挿入と追加の部品があるので違和感が少ない。
- 参考 (LM Studio・Claude・ChatGPT の入力欄): 送信ボタンが、テキストの入力域に融合したような形になっている。
- オーナーの問い: 発言ボタンを入力域の横に置くか。そうすると単独チャットとのバランスが悪くなるか。

着手時に決めること:
- 送信・発言ボタンを入力域の中に収めるか、横に置くか。オーナーに形を見せて決める。
- 消す説明文の行き先。
  - 自動進行の停止がターン境界で効くことは、design (multi-agent-chat-design.md §6) が「UI にも明示する」と求めている (docs/current-spec §11.6 も同じ)。消すなら、補助表示に移すか、自動進行の実行中だけ出すかを決め、design と current-spec を直す。
  - 切断しても進行中のターンがサーバー側で完走する旨も同じ扱いにする。
- 無効の理由の語 (TASK-47 で `aria-describedby` と title に持たせた) と、処理中の語と幅を保つこと (doc-8 §6.1) は、形を変えても保つ。

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
オーナー判断 (2026-09-27、着手時): 灰色の箱 (ComposerBox) は残し、中身を「入力欄 → その下に操作の行 (左に選択欄と補助の操作、右端に送信・介入)」にそろえる。単独チャットは今の形がほぼ素案どおり。
1. 共通の入力欄: 自動で伸びる高さ (最小3行・最大20行) と、IME 変換中を除く Enter での送信を components/ComposerTextarea にまとめ、両画面で使う。
2. 次の発言者 (サーバー): TurnEngine.NextSpeaker (読み取り専用。manual は null) と GET /api/chats/{chatId}/turns/next ({participant, historyLimit})。speaker フレームに next を足す (round_robin・facilitator_alternating だけ。weighted は発言の中身で変わるので null)。フロントは規則を複製しない。
3. 多人数会話の箱: [発言者の選択欄][1 ターン進める][自動進行](?) … [n ターン目][介入する]。選択欄は manual の待機中だけ選べ、それ以外は無効 (理由つき) で「次の発言者: 名前」を出す。実行中で次が決まらないとき (weighted・manual・speaker 到着前) は「発言中: 名前」と処理中の図形。
4. 注記の行き先: 停止がターン境界で効く旨は (?) の補助表示へ (履歴が直近30発言までである旨も同じ補助表示に)。切断時の完走の注記は消す (単独チャットと同じ挙動)。自動進行中・manual・2人未満・指名なしはボタンの無効の理由に既にあるので行を消す。一時チャットで保存できない旨はメモリ保存ボタンの理由にあるので箱からは消す。進行役不在・停止受付・失敗・保存済みの告知は、あるときだけ入力欄の上に出す。
5. ターン数のバッジ: 参加者の発言数 (実行中は +1)。発言総数が履歴の上限を超えたら語を足して知らせる。
6. design (§4.1・§5・§6) と current-spec (§11.6、ja・en) を直す。トークン消費のグラフは別タスクに起票する。
7. go test ./...・pnpm check:client・pnpm build:client。Vite 開発サーバー + Playwright (scratchpad に一時導入、/api は route で固定) で4配色の比・キーボード到達・配置を測る。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## オーナーの判断 (2026-09-27、着手時)
- ボタンの位置: 灰色の箱 (ComposerBox) は残し、その中を「入力欄 → その下の操作の行」にする。送信・介入するは行の右端 (素案。単独チャットの今の形と同じ)。AC#1 の「入力域の中か横」のどちらでもなく、入力域の下の行の右端を採った。
- 発言者の選択欄: manual 以外の規則では無効にし、規則が決めた次の発言者を出す (1 回だけの上書きは採らない。サーバーが manual 以外の指名を拒む判断はそのまま)。
- 次の発言者の出どころ: この PR でサーバーに持たせる (フロントは規則を複製しない)。
- トークン消費のグラフ: 別タスクにする → TASK-60 を作った。
- 切断時の完走の注記は消す (単独チャットでも同じ挙動で、この画面だけの注記ではない)。

## 変えたもの
- サーバー: `TurnEngine.NextSpeaker` と `GET /api/chats/{chatId}/turns/next` (`{ participant, historyLimit }`、manual と空の編成は null。ターン実行権は取らない)。`speaker` イベントに `next` を足した (round_robin・facilitator_alternating だけ。保存前の発言を「誰が話したか」だけの行として足して `selectSpeaker` を読む。weighted は発言の中の呼びかけを読むので null)。`turnHistoryLimit` を `TurnHistoryLimit` として公開した (数の写しをフロントに持たせないため)。design §4.6.6 は事前問い合わせを退けていたので、表示だけに使う形で採る理由を追記した。
- 共通の入力欄: `components/ComposerTextarea` (最小3行・最大20行で伸びる、Enter で送信・Shift+Enter で改行・IME の確定の Enter は送らない)。単独チャットの最小の高さは 110px から3行分 (92px 前後) になった。多人数会話にも Enter の送信と伸びる高さが付いた。
- 多人数会話の箱: 入力欄の下の1行に [発言者の選択欄][1 ターン進める][自動進行](?) … [n ターン目][介入する]。
  - 選択欄: manual の待機中だけ選べる。それ以外は無効 (理由: 規則が決める / 自動進行中は変更できない / 発言の生成中は変更できない) で「次: 名前」。ターン中で次が決まらないとき (weighted・manual・speaker の到着前) は「発言中: 名前」と処理中の図形。図形は選択欄の中 (矢印の左) に常に取った余白に重ねる (横に置くと、ターンの無いあいだ空の枠が隙間に見えた)。ターン中に介入したら、フレームの next を表示から外す。自動進行でターンが続くあいだの取り違えを避けるため、done の直後は読み直しが返るまでフレームの next を使う。
  - 自動進行のボタンの語を「自動進行」/「停止」に縮めた (素案の語。インスペクタを出した 1280px で行が3段に折れたため)。停止を受け付けてから進行中のターンが終わるまでは「停止」のまま処理中。前は「停止を受け付けました…」の行が、手動の「1 ターン進める」の最中にも出ていた (stopPending が「自動進行でない かつ ターン中」だったため)。
  - (?) の補助表示: 停止がターン境界で効くことと、各発言者が読むのは直近 30 発言 (人間の発言を含む) までであること。
  - ターン数: 状態バッジ (doc-8 §6.5 の中立) で参加者の発言数、実行中はそのターンの番号 (開始時に固定する。done の transcript と実行中の +1 が重なって1つ多く見えるのを避ける)。発言の総数が 30 を超えたら「古い発言は参照外」を語で足す。警告の面 (Badge warm) は Solarized Light / Dark で語の比 4.47 と 4.5:1 を割ったので使わず、語だけで伝える。
  - 「発言」を「介入する」にした (素案の語)。入力欄の名前は「会話への発言」。
  - 常設の行を消した: 自動進行中・manual の自動進行・2人未満・指名なし (各ボタンの無効の理由にある)、一時チャットで保存できない旨 (保存ボタンの理由にある)、ターン実行中の話者名 (選択欄へ)、結論の要約中 (見出しのボタンが処理中を出す)、停止の注記 (補助表示へ)、切断時の注記 (消した)。残した行はあるときだけ出す: ターン・結論・介入の失敗、進行役が編成にいない旨、メモリに保存した旨。
- design (§4.1・§4.6.6・§5・§6) と current-spec (ja・en の多人数会話の流れと画面) を直した。

操作 (Chromium と WebKit の両方):
- Tab の順: 入力欄 → 発言者の選択欄 → 1 ターン進める → 自動進行 → (?) → 介入する。無効の選択欄も焦点を受け、理由を title と aria-describedby に持つ。(?) は Enter で開き、本文が出る。
- Shift+Enter で改行し、Enter で送る (送られた本文は「一行目\n二行目」)。
- round_robin の1ターン: 待機中「次: 肯定側」→ 開始直後「発言中: 肯定側」+ 図形 → speaker (next つき) の後「次: 否定側」(図形なし) → 終了後、読み直した次の発言者。バッジは 4 → 実行中 5 → 終了後の transcript の数。weighted では speaker の後も「発言中: 司会」+ 図形。
- 「1 ターン進める」の幅は待機中と処理中で同じ (Chromium 164.6px、WebKit 158.2px)。
- 自動進行: 実行中はボタンが「停止」、選択欄の理由は「自動進行中は変更できません」。停止を押すと「停止」のまま aria-busy、ターンが終わると「自動進行」に戻る。
- 配置: 両エンジン、両画面、1280・1000・800・600・360px で横スクロールなし。箱の高さは、インスペクタを閉じた 1280px で多人数会話 217px (Chromium) = 単独チャット 217px (1行に収まる)。インスペクタを出した 1280px (中央の列 約620px) では右端の [n ターン目][介入する] が次の行に回り 273px (素案の要素を1行に並べるには約 810px 要る)。前の多人数会話の箱は説明文 5〜6 行を持っていた。
- `go test ./...`・`go vet ./...`・`pnpm check:client`・`pnpm build:client` が通った。
