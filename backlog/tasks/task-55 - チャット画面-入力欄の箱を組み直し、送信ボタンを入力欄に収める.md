## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-47 (#47) の後のオーナーの実窓の確認 (2026-09-26) で出た、入力欄の箱 (`Composer` / `ComposerBox`) についての指摘。単独チャットと複数エージェントチャットの両方に掛かる。

指摘:
- 複数エージェントチャットの入力欄の箱が場所を取りすぎている。「停止はターン境界で効きます…」「この画面が切断されても…」の説明文は削除できないか。
- 複数エージェントチャットの、入力欄の下の空間がもったいない。単独チャットは、同じ位置にドキュメントの挿入と追加の部品があるので違和感が少ない。
- 参考 (LM Studio・Claude・ChatGPT の入力欄): 送信ボタンが、テキストの入力域に融合したような形になっている。
- オーナーの問い: 発言ボタンを入力域の横に置くか。そうすると単独チャットとのバランスが悪くなるか。

着手時に決めること:
- 送信・発言ボタンを入力域の中に収めるか、横に置くか。オーナーに形を見せて決める。
- 消す説明文の行き先。
  - 自動進行の停止がターン境界で効くことは、design (multi-agent-chat-design.md §6) が「UI にも明示する」と求めている (docs/current-spec §11.6 も同じ)。消すなら、補助表示に移すか、自動進行の実行中だけ出すかを決め、design と current-spec を直す。
  - 切断しても進行中のターンがサーバー側で完走する旨も同じ扱いにする。
- 無効の理由の語 (TASK-47 で `aria-describedby` と title に持たせた) と、処理中の語と幅を保つこと (doc-8 §6.1) は、形を変えても保つ。
