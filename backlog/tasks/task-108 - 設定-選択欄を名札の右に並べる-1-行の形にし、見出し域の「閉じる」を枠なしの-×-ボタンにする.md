## 背景

設定モーダルの各項目は、名札の下に選択欄が全幅で伸びる縦積み (`Field` が `flex-direction: column`) で、項目が少ない「外観」「言語」の区画でも縦に長い。
mallow の設定画面は、名札を左、選択欄を右に置いて 1 項目 1 行に収め、選択欄の幅は選択肢の語に合わせている。ユーザーはこの形のほうがすっきりしていて好みとのこと。
区画の見出し (`SubsectionTitle`) は mallow では目立たなすぎるので、snz_studio の現行のままにする。

見出し域の閉じるボタンは、どのモーダルも語の「閉じる」を通常の変種のボタン (`ActionButton variant="normal"`) で出している。
mallow は枠なしの × を見出し域の右端に置いている。共通仕様でもモーダルの閉じるは doc-8 §6.2 のアイコンのみボタンとされており (doc-9 §6.6 の構造)、
doc-8 §6.1 の「控えめ」変種 (面と輪郭を持たない) をアイコンのみボタンに当てれば枠なしにできる。
モーダルごとに見た目が違うのを避けるため、× は見出し域に「閉じる」を持つ全モーダルに当てる (ユーザー判断、2026-10-25)。

## 変えるもの

### 設定モーダルの選択欄

- 選択欄の項目 (テーマ・モード・表示言語・LLM の Think の強さ・LLM 応答フォーマット・埋め込みの取得元) を、名札を左、選択欄を右に置く 1 行にする。選択欄の幅は選択肢の語に合わせる。
  - 名札の横に接続のバッジを持つ項目 (埋め込みの取得元を外部にしたとき) は、名札とバッジを左に置く。
  - 補足の文 (Think の強さの説明、埋め込みの状態・ダウンロードの進捗) は、その行の下に全幅で置く。
  - モーダルの幅が足りず名札と選択欄が 1 行に収まらないときは、現行の縦積みに折り返す。
- 1 行入力 (エンドポイント・モデル名) は値が長いので、現行の縦積みのままにする。

### 全モーダルの閉じるボタン

- 見出し域に語の「閉じる」を持つ 10 のモーダルすべてで、閉じるボタンを枠と面を持たない × のアイコンのみボタンにする。
  - 対象: SettingsModal・CreateProjectDialog・ImageDocumentDialog・ProjectDetailPage の 4 つ (882・1010・1052・1114 行付近)・ChatPage の 3 つ (912・952・985 行付近)。
  - 呼び出し側ごとに組み立てず、`Dialog.tsx` に見出し域の閉じるボタンを 1 つ用意し、全モーダルがそれを使う形にする。
- 押せる領域 (`snzTokens.size.control`)・hover / 押下の面・フォーカス枠・処理中の無効とその理由 (`settings.savingClose`・`dashboard.creatingClose` など、呼び出し側が今渡している `disabledReason`) は今と同じに保つ。読み上げには「閉じる」の語を渡す。
- 破棄前確認・Escape・焦点の返却など、閉じる操作の振る舞いは変えない。

## 対象外

- UpdateDialog の「閉じる」。見出し域ではなく操作域 (手動更新の案内で「リリースを開く」と並ぶ取り消し側) にあり、doc-9 §6.6 の操作域の取り消しとして語のボタンのままにする (ユーザー判断、2026-10-25。着手時に、見出し域の「閉じる」が 11 ではなく 10 と判明)。
- 右側の区画 (プロジェクト詳細・多人数会話のインスペクタ) を閉じるボタン (`RegionCloseButton`)。枠を持つ現行のままにする (ユーザー判断、2026-10-25)。ヘッダーの開閉ボタン (`RegionToggleButton`) と対になる部品で、モーダルの × とは役割が違う。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- 着手時の判断 (ユーザー判断、2026-10-25): UpdateDialog の「閉じる」は見出し域ではなく操作域の取り消しだったので対象から外し、AC #5 と本文の数を 11 から 10 に直した。AC #8 (snz-design doc-17) は、これまでの記録と同じく、この PR のマージ後に統合済みリビジョン付きで snz-design 側に記録する。
- 閉じるボタン: 呼び出し側に部品を渡させる形ではなく、`DialogHeader` に `onClose` / `closeDisabledReason` を足し、見出し域の右端 (他のボタンの後) に × を描く形にした。呼び出し側が部品を選べないので、置き場所と見た目がモーダルごとにずれない。プロジェクトメモリは「整理」を `actions` に残し、× がその右に来る。
- × の見た目は doc-8 §6.1 の控えめ変種をアイコンのみボタンに当てた `SubtleIconButton` (`IconButton` の派生): 輪郭と面は透明、図形はアクセントの色 (doc-8 §6.1 のトークン用途で控えめの語は `--snz-accent`。snz-design の Storybook のモーダルの × も同じ)、hover・押下の面と焦点の枠は `IconButton` のまま。無効のときは doc-8 §5.4 の破線の輪郭を `iconBorder` (= line-control) で戻す (輪郭が透明のままでは破線が見えず、形で無効を述べられないため。Storybook の控えめの無効と同じ)。`ActionButton` に `subtle` を足して通した。
- 選択欄の 1 行化: `FieldRow` (ui.tsx) を足し、`Field` (label) の中に名札 (先頭の子) と選択欄を並べる。名札は `flex: 999 1 12rem`、選択欄は `width: auto` で選択肢の語の幅。両方が 1 行に乗っている間は名札が空きをほぼ全部取り、収まらなくなると選択欄が折り返し、1 人で乗った行では全幅に伸びるので、狭い幅では従来の縦積みと同じ見た目になる。メディアクエリにしなかったのは、モーダルの幅は窓の幅と一致せず、名札と選択肢の語の長さ (言語で変わる) で決めたいため。補足の文・進捗は `Field` の中、行の下に残した。埋め込みの取得元は先頭の子に名札とバッジをまとめた。1 行入力は縦積みのまま。
- 測定環境: macOS 26.7.1、この変更のビルドと main (`bce3c37`) のビルドを `vite preview` で配り、/api を Playwright 1.62.0 の route で固定、Wails の bindings は init script で差し替えた。描画エンジンは Playwright の Chromium (chromium-1234) と WebKit (webkit-2336)。どちらも headless で WKWebView ではない。
- AC #1: 1280×800 で 6 項目 (テーマ・モード・表示言語・Think・応答フォーマット・埋め込みの取得元) が名札と同じ行 (中心の高さの差 4px 未満、選択欄が名札の右)。選択欄の幅は flex を外したときの幅と一致 (Chromium 127 / 164 / 98 / 159 / 153 / 268px、WebKit 127 / 157 / 98 / 152 / 153 / 259px、行の幅 784px)。
- AC #2: Think の説明、埋め込みの状態 (内蔵の準備完了)、外部にしたときの説明と名札の横の「接続済み」バッジ、ダウンロード中の進捗 (進捗の行と「その間は〜」) が、行の下に全幅 (784px / 360px 幅では 236px) で出ることを両エンジンで確かめた。
- AC #3: 360×640 で 6 項目とも選択欄が名札の下に回り、全幅 (236px) に伸びた。文書・本体域とも横のはみ出し 0 (内蔵・外部・ダウンロード中の 3 状態 × 両エンジン)。
- AC #4: 区画の見出し (外観・言語・接続・埋め込みの作り直し・更新) の font-size / weight / line-height / color / margin / 寸法 / 区画の中の位置を、1280・360 幅 × 両エンジンで main のビルドと比べ、すべて一致した。
- AC #5・#6: 10 のモーダル (設定・プロジェクト作成・画像文書の追加・ドキュメント詳細・プロジェクトの題名・システムプロンプト・プロジェクトメモリ・チャットの題名・ドキュメント追加 (チャット)・編集レビュー) で、見出し域に語の「閉じる」ボタンが 0 個、名前「閉じる」の × が 1 個で見出し域の最後のボタン。輪郭・面は透明、38×38px (`size.control`)、hover の面 rgb(226, 230, 237) (標準 Light)、キーボードで届いたときの :focus-visible で焦点の枠 2px +1px。処理中の無効は、プロジェクト作成・プロジェクトの題名・設定の保存を応答の来ない状態に止めて確かめた: `aria-disabled="true"`、`aria-describedby` に従来どおりの理由 (dashboard.creatingClose / project.savingClose / settings.savingClose)、破線の輪郭 rgb(118, 127, 140)・不透明度 0.45、押しても閉じない。headless の WebKit は Tab でボタンへ移らない既定なので、プロジェクトメモリの × (先頭のボタンが「整理」) の焦点の枠は、キー操作の直後に焦点を当てて確かめた。
